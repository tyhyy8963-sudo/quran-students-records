# تشغيل المشروع بعد السبرنتات 1–14

## 1. المتغيّرات البيئية

انسخ `.env.example` إلى `.env` ثم:

```bash
php artisan key:generate
```

> **تنبيه:** المفتاح الذي كان مكشوفًا في `resources/views/` يجب اعتباره محروقًا.
> شغّل `key:generate` على **كل** بيئة. تدوير المفتاح يُبطل الجلسات والكوكيز
> المشفّرة الحالية، فسيُطلب من المستخدمين تسجيل الدخول من جديد — مرّة واحدة.

## 2. قاعدة البيانات

```bash
php artisan migrate
```

مدير + ثلاثة معلّمين أحدهم معطَّل عمدًا، 3 حلقات، 114 سورة، 26 طالبًا بحالات

من الناس صعودًا، تشمل سورًا قيد الحفظ ومراجعات لا ترفع النسبة):

mysql -u root -p < teacher_db.sql

## 3. الأصول الأمامية (Vite)

الواجهات مبنية على نظام تصميم موحّد (`resources/css/app.css` وresources/js/app.js`)
مُجمَّع عبر Vite بدل وسوم `<link>`/`<script>` يدوية لكل صفحة. منذ S8، يوجد
مدخل Vite ثانٍ منفصل: `resources/js/student-timeline.js` (يحمّل Chart.js
لرسم منحنى التقدّم) — يُحمَّل فقط في صفحة سجلّ الطالب، فلا تحمّله صفحات
الدخول/التسجيل التي لا تحتاجه.

```bash
npm install
npm run build      # للإنتاج — ينتج public/build/ (يبني المدخلين معًا)
# أو أثناء التطوير:
npm run dev         # خادم Vite بإعادة تحميل فورية
```

> إن ظهرت صفحة بيضاء أو خطأ "Vite manifest not found"، فهذا يعني أن
> `npm run build` لم يُشغَّل بعد. الاختبارات الآلية (`phpunit`) لا تحتاج هذه
> الخطوة — تتجاوز Vite تلقائيًا (`withoutVite()` في `tests/TestCase.php`).

## 4. عامل الطابور

**لم يعد مطلوبًا لتشغيل النظام بعد S13.** الاستخدام الوحيد للطابور كان إرسال
رسائل استعادة كلمة المرور، وقد أُزيلت الاستعادة بالبريد بالكامل (لا بريد في
المنظومة). جدول `jobs` باقٍ في البنية لأي استخدام مستقبلي، لكن لا شيء يكتب
فيه اليوم، ولا حاجة إلى تشغيل `php artisan queue:work` ولا إلى إعداد
`MAIL_*` إطلاقًا.

**لا حاجة إليها.** لا يرسل النظام أي رسالة بريدية بعد S13: لا تسجيل ذاتي،
ولا تحقق من بريد، ولا استعادة كلمة مرور برابط. قيم `MAIL_*` في `.env.example`

## 9. المسارات الجديدة (S9–S10)

| المسار | الوظيفة |
|---|---|

> **لا تصدير PDF/Excel حقيقي في هذا الإصدار.** بيئة التطوير التي بُني بها

> البديل: تنزيل CSV حقيقي (يُفتح في إكسل مباشرة) وزرّ "طباعة / حفظ كـ PDF"
> يستخدم خاصية الطباعة المدمجة في المتصفّح. إن رغبت لاحقًا في PDF/Excel
> حقيقيين، ثبِّت `barryvdh/laravel-dompdf` و`phpoffice/phpspreadsheet` عبر
> Composer من بيئة تصل Packagist، دون الحاجة لتغيير `ReportController` في
> بنيته العامة — فقط إضافة دالة تصدير جديدة بجانب `exportCsv()`.

## 10. تطبيق ويب تقدّمي (PWA) ووضع دون اتصال (S12)

المشروع الآن قابل للتثبيت كتطبيق (`public/manifest.json` + `public/sw.js`).

> **عامل الخدمة (Service Worker) يحتاج "سياقًا آمنًا": HTTPS، أو `localhost`
> تحديدًا.** يعمل تلقائيًا في `http://localhost:8000` (أو أي منفذ محلي)، لكنه
> **لن يُسجَّل إطلاقًا** إن فُتح الموقع عبر عنوان IP عادي على الشبكة المحلية
> (مثل `http://192.168.1.5`) بلا HTTPS — قيد أمان من المتصفّح نفسه لا عطل في
> المشروع. بقية التطبيق يعمل بشكل طبيعي بدون عامل الخدمة، فقط دون تثبيت
> PWA أو تخزين مؤقّت دون اتصال.

**نطاق "دون اتصال" محدود عمدًا:** تسجيل الحضور وإضافة سجلّ زمني فقط (كما
ورد حرفيًا في خطة السبرنتات). إن انقطع الاتصال أثناء استخدام هاتين
الشاشتين، يُحفَظ الطلب في `localStorage` الخاص بالمتصفّح ويُعاد إرساله
تلقائيًا عند عودة الاتصال. هذا الطابور **محلي لكل جهاز/متصفّح على حدة** —
لا يتزامن بين جهازَي المعلّم، ويُفقَد إن مسح بيانات الموقع من المتصفّح.

## 11. الوضع الليلي

زرّ 🌙/☀️ في الرأس (وفي أعلى صفحات الدخول/التسجيل) يبدّل الوضع، ويُحفَظ
الاختيار في `localStorage` — لا إعداد خادم مطلوب. بلا اختيار محفوظ، يتبع
التطبيق تفضيل نظام تشغيل الزائر (`prefers-color-scheme`) تلقائيًا.

## 12. نظام الحسابات المغلق (S13)

المنظومة داخلية بالكامل: **لا أحد ينشئ حسابًا لنفسه**، ولا بريد إلكتروني، ولا
استعادة كلمة مرور من الواجهة. المسارات `/register` و`/forgot-password`
و`/reset-password` لم تعد موجودة أصلًا (تعطي 404 لا صفحة فارغة).

### أول تنصيب — إنشاء حساب المدير

بما أنه لا تسجيل ذاتي لأول مستخدم أيضًا، يُنشأ أول حساب من الخادم:

```bash
php artisan keshf:create-admin --username=admin --name="مدير المنظومة"
```

بلا `--password` يولّد النظام كلمة مرور ويعرضها **مرّة واحدة** في الطرفية.

### دورة حياة حساب المعلّم

| الحالة | ما يفعله المدير |
|---|---|
| معلّم جديد | «حسابات المعلّمين» ← «+ حساب معلّم جديد». اترك كلمة المرور فارغة ليولّدها النظام، ثم سلّم البيانات للمعلّم مباشرة (تُعرض مرّة واحدة فقط). |
| نسي كلمته | زرّ «كلمة مرور جديدة» أمام اسمه — كلمته القديمة تتوقّف فورًا. |
| توقّف عن التدريس | زرّ «تعطيل»: يفقد الدخول فورًا (حتى لو كانت جلسته مفتوحة على هاتفه)، وتبقى سجلّات طلابه كاملة. |
| حساب أُنشئ خطأً | «حذف» — يظهر فقط لمن لا طلاب له. المعلّم صاحب الطلاب لا يُحذف (الحذف يمحو طلابه وسجلّاتهم بـcascade)، بل يُعطَّل. |

> **كلمة المرور تُعرض مرّة واحدة ولا تُسترجَع.** هي مخزَّنة مُجزّأة كما يجب،
> والبديل عن ذلك هو حفظها بنص صريح في مكان ما — وهو أسوأ ما يُفعل بكلمات
> المرور. فقدانها يعني إعادة تعيين لا استرجاعًا.

### المعلّم لا يغيّر كلمة مروره

قرار مؤسسي صريح: لا شاشة ولا زرّ ولا مسار خلفي. صفحة `/edit-password` تعطي
403 لحساب المعلّم، وكلمته تُعاد من لوحة المدير وحدها.

### طوارئ: المدير نفسه فقد دخوله

لا أحد فوق المدير في النظام، ولا استعادة بالبريد — فالمسار الوحيد من الخادم:

```bash
php artisan keshf:reset-password admin --activate
```

يطبع كلمة مرور جديدة (أو مرّر `--password=...`)، ويعيد تفعيل الحساب إن كان
معطَّلًا. يعمل الأمر مع أي اسم مستخدم، مديرًا كان أو معلّمًا.

> **لا يبقى النظام بلا مدير أبدًا:** لا يمكن حذف آخر حساب مدير نشط، ولا
> تعطيله، ولا تحويله إلى معلّم — الحارس في الموديل نفسه، فيسري على كل مسار
> (الواجهة، أوامر artisan، tinker) لا على الشاشة المكتوبة اليوم فقط.

## 13. نسبة الحفظ بترتيب الحفظ المعكوس (S14)

الحفظ في الحلقات يبدأ من آخر المصحف ويصعد، فالنسبة تتبع هذا الترتيب لا ترتيب
المصحف:

```
رتبة السورة في الحفظ = 115 − رقم السورة     (الناس = 1 … البقرة = 113)
نسبة الطالب = (مجموع تغطية كل سورة) ÷ 113 × 100
تغطية السورة = آياتها المحفوظة ÷ عدد آياتها  (بين 0 و1)
```

- إتمام **الناس** وحدها ≈ **1%**، وإتمام كل شيء = **100%**.
- **الفاتحة مستثناة كليًا**: تُسجَّل وتُسمَّع وتُراجَع كأي سورة، لكنها لا تدخل
  المقام (113) ولا تضيف شيئًا إلى النسبة — وتظهر في قائمة السور مذيّلة بـ
  «(لا تُحتسب في النسبة)» حتى لا تُختار ظنًّا أنها تُقدّم الطالب.
- **النوع «حفظ» وحده** يرفع النسبة؛ «مراجعة» و«تسميع» أحداث على مقطع سبق حفظه.
- **الجلسات المتداخلة تُحسب مرّة واحدة**: تسجيل 1–20 ثم 15–40 يعطي 40 آية لا 46.
- **السورة قيد الحفظ تحرّك النسبة بمقدار ما أُنجز منها** — فلا تتجمّد النسبة
  شهورًا أثناء حفظ سورة طويلة كالبقرة.
- قائمة السور في كل الشاشات مرتّبة بترتيب الحفظ (الناس أولًا)، فالسورة التالية
  للطالب قرب أعلى القائمة لا بعد تمرير مئة سورة.

> **تغيير سلّم القياس لاحقًا لا يمسّ الكود:** الرتبة والاستثناء عمودان في جدول
> `surahs` (`memorization_order`, `excluded_from_progress`)، والحساب كلّه في
> صنف واحد (`app/Support/MemorizationProgress.php`) تستدعيه اللوحة وصفحة
> الطالب والتقارير معًا. لو أردت وزنًا بعدد الآيات بدل وزن متساوٍ لكل سورة،
> فالتغيير في قيم عمود واحد.
